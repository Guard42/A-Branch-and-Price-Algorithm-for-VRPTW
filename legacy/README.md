# 历史实现存档（反面教材 / 学习笔记）

本目录完整保留本项目最初的一版可运行实现：对 dengfaheng/BPVRPTW（Java）的 AI 移植。
七个扁平模块经 `git mv` 按原始字节原样封存于此，未做任何修改，仅作历史参照与教学反例。
新的库级实现位于仓库根目录的 `bpvrptw/` 包，与本目录零代码耦合。

> 结论先行：这一版能在小算例上跑通，但正确性与工程性均有实质缺陷（见下方 D1–D9），
> 请勿将其当作参考实现，也不要在本目录上继续开发。

## 文件清单

| 文件 | 原职责 |
| --- | --- |
| `paramsVRP.py` | Solomon 算例读取与全局参数初始化 |
| `route.py` | 路线对象与成本计算 |
| `SPPRC.py` | ESPPRC 标签结构与扩展过程 |
| `columnGen.py` | 列生成主循环（受限主问题用 Gurobi 求解） |
| `branchBound.py` | 分支定界框架与分支启发式 |
| `main.py` | 命令行入口 |
| `solVisualization.py` | 解的 matplotlib 可视化 |

## 如何运行

```bash
cd legacy
python main.py
```

- 依赖：`gurobipy`（需 Gurobi 许可证）与 `matplotlib`；
  可先 `pip install "bpvrptw[gurobi,plot]"` 再进入本目录运行。
- 参考输出：Solomon `c101` 前 25 客户 cost=191.70、routes=3，约 2.7 s、40 轮列生成、753 列。
- 新包默认 LP 后端是 HiGHS（`highspy`）；legacy 代码硬绑定 Gurobi，无法受益于它。

## 缺陷目录 D1–D9

以下问题在移植审查中逐条确认，每一条都对应新实现里的一条设计决策：

- **D1** U/P 标签集合按插入索引排序而非标签代价，破坏 best-first 搜索与
  “最负列优先”选列准则（Java 原版用 TreeSet + 标签比较器同时保证两者）。
- **D2** `label.__lt__` 引用了未定义的 `A`/`B`（潜在 `NameError`），`__eq__` 实现亦不正确；
  因排序根本不走比较器，这段错误沦为死代码——错得悄无声息。
- **D3** 终点仓库下标移植错误：守卫 `!= nbclients+1` 在 Python 的 0 基索引下恒为真
  （真正的终点下标是 `nbclients-1`）；向仓库施加分支边时会错误地禁止其余路径回仓。
- **D4** 列生成每发现一条新列就整体删除并重建 Gurobi 模型，既丢失热启动，
  又造成平方级的重复建模浪费。
- **D5** 分支启发式 `routes[i].get_cost()` 用顶点 id 当下标去查路线表
  （承袭上游 Java 版的怪癖，语义完全错位）。
- **D6** 全程裸 `print` 输出；`init_params` 吞掉一切异常，出错时静默带病继续运行。
- **D7** 硬编码绝对路径（`main.py` / `solVisualization.py`），换一台机器即不可复现。
- **D8** 无界循环：列生成 `while True` 无收敛上限、ESPPRC 扩展无支配/数量截断，
  实测在 c104 上直接挂起。
- **D9** 终解过滤弹出“最早创建”的标签而非“最负成本”的标签，选列准则失真。
